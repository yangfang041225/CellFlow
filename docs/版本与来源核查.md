# 官方来源与兼容性核查

核查日期：2026-10-24。以 **PyPI 发行包元数据 + 实际安装后的真实 API** 为依据；
官方文档里的 latest/stable 示例可能早于或晚于本机发行版，**运行版本以 `environment-venv.lock.txt` 与每次任务的 `environment.json` 为准**。

## 一、方法来源与结论

| 方法 | 官方入口 | 核查结论 |
|---|---|---|
| scVelo | [文档](https://scvelo.readthedocs.io/en/stable/VelocityBasics.html)、[PyPI](https://pypi.org/project/scvelo/) | 需要 S/U 两层；dynamical 必须先 `recover_dynamics`。0.3.4 的 `pp.filter_and_normalize` 已不再接收 `n_top_genes`/`log1p`，旧教程的合并调用会报错 → 适配器改为显式逐步调用 |
| RegVelo | [PyPI 0.4.2 元数据](https://pypi.org/pypi/regvelo/0.4.2/json)、[官方工作流](https://regvelo.readthedocs.io/en/latest/getting_started.html) | Python≥3.10；发行版约束 `scvi-tools<1.2.1`、`torch<2.6`、`SciPy<1.16`。0.4.2 的 `tools/_inferred_grn.py` **写死 `cuda:0`** → 本 CPU 方案不调用该函数，不输出调控边 |
| veloVI | [scvi-tools 模型说明](https://docs.scvi-tools.org/en/stable/user_guide/models/velovi.html) | 和 RegVelo 不是同一个模型；接入需要保存训练过程、后验样本与不确定性。当前未接入 |
| DPT / PAGA | [DPT](https://scanpy.scverse.org/en/stable/generated/scanpy.tl.dpt.html)、[PAGA](https://scanpy.scverse.org/en/stable/generated/scanpy.tl.paga.html) | DPT 需要 diffusion map 与根细胞；PAGA 是群间拓扑，不应被转述为有向谱系 |
| CellRank 2 | [官方文档](https://cellrank.readthedocs.io/en/stable/) | 见下方“CellRank 专项” |

| DeepVelo | [bowang-lab 实现](https://github.com/bowang-lab/DeepVelo) | 官方 README 要求较旧 Python 与 DGL，默认 GPU；同名其他项目不是同一实现。当前未接入 |
| VeloAE | [官方代码](https://github.com/qiaochen/VeloAE) | 低维速度与基因空间速度不可直接逐元素比较，需要额外映射。当前未接入 |

## 二、CellRank 专项（本期新接入）

- **版本选择**：CellRank 2.1+ 要求 **Python ≥3.12**；本机是 **3.11**，所以固定 **`cellrank==2.0.7`**（最后一个支持 3.11 的发行版）。
  依赖很小（`docrep`、`pygam`、`pygpcca`、`progressbar2` 等），可以装在主环境里，不需要独立环境。
- **依赖注意**：`pygpcca 1.0.4` 在元数据里钉了 `jinja2==3.0.3`。Streamlit 1.66 **不依赖 jinja2**，所以这个替换不影响界面；
  如果你的机器上还有别的工具需要 jinja2≥3.1，请把 CellRank 装进独立环境。
- **API 形态**：CellRank 2 **没有** `cr.tl` 模块（那是 1.x 的 API）。本期使用：
  `cr.kernels.PseudotimeKernel(adata, time_key='dpt_pseudotime')` →
  `compute_transition_matrix(n_jobs=1, backend='threading', show_progress_bar=False)` →
  `cr.estimators.GPCCA(kernel)` → `compute_schur` → `compute_macrostates(n_states, cluster_key)` →
  `predict_terminal_states()` → `compute_fate_probabilities(use_petsc=False)`。
- **为什么关进度条**：`cellrank` 的 `parallelize` 在 `show_progress_bar=True` 时会创建 `multiprocessing.Manager()`；
  受限环境（以及某些企业策略）会因命名管道/共享内存被拦而失败。本程序统一传 `show_progress_bar=False`，
  并在 `n_jobs=1` 下运行，牺牲速度换取可复现与稳定。
- **已知兼容缺陷（本期实际遇到并绕过）**：`cellrank 2.0.7` 的 `Lineage` 对象用旧签名调用
  `anndata 0.12.19` 的 `write_basic(..., elem=...)`，直接 `write_h5ad` 会抛
  `TypeError: write_basic() got an unexpected keyword argument 'elem'`。
  适配器的处理：写盘前把 `obsm` 里的 ndarray 子类（`Lineage` 就是其中之一）转成**纯 ndarray**，
  并把第三方模型对象从 `uns` 里剔除，再写 `analysis.h5ad`。这是**写入兼容**问题，不影响数值结果。
- **内存约束**：不装 `petsc4py` 时 `compute_schur` 走 `method='brandts'`，会把细胞×细胞矩阵**稠密化**。
  6000 细胞时约 0.3 GB，2 万细胞时约 3 GB 以上。因此适配器在 **>6000 细胞**时直接拒绝并说明原因，
  建议先做受控子集，或改用 DPT + PAGA 看方向。
- **科学注意**：PseudotimeKernel + GPCCA 可能把“拟时序早端”的群也识别成终末状态（吸收态）。
  适配器会计算每个终末状态的平均拟时序，低于整体中位数时写入警示，
  避免被误读成“细胞最终回到早期状态”。

## 三、scVelo 0.3.4 实际接口差异

本机安装 scVelo 0.3.4。`pp.filter_and_normalize` 已不接收 `n_top_genes`，函数体内也不再执行 HVG 与 log1p；
旧教程的合并调用会把未知参数传给 `normalize_per_cell` 并报错。适配器改为显式序列：

```
scv.pp.filter_genes(min_shared_counts)
scv.pp.normalize_per_cell(counts_per_cell_after=1e4, layers=['spliced','unspliced'], enforce=True)
scanpy.pp.log1p
scanpy.pp.highly_variable_genes(n_top_genes, flavor='seurat')
scanpy.pp.pca / scanpy.pp.neighbors / (可选 umap)
scv.pp.moments
scv.tl.velocity(mode=...) → velocity_graph → velocity_confidence → velocity_embedding → velocity_pseudotime
dynamical 额外：scv.tl.recover_dynamics → scv.tl.latent_time
```

每一步都记录进 `calls.json`，`run.log` 保留上游库的原始警告。

## 四、Leiden 与 igraph

`scanpy.tl.leiden(flavor='igraph', n_iterations=2, directed=False)` 只需要 `python-igraph`，**不需要 `leidenalg`**。
这样主环境可以少一个需要编译的依赖，也避免与其它包的版本冲突。群数会随 `leiden_resolution` 变化，界面上可调。
