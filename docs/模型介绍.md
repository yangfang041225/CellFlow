## 一键分析（推荐）：我不想一个个挑方法：能不能一次跑完体检、分群、轨迹，有剪接层就加速度和命运，最后给我一份报告？

### 一键分析（推荐流程）（`auto`，CellFlow auto pipeline）

- **当前状态**：可运行
- **必需输入**：无
- **可选输入**：起始细胞 + 依据（给了就用 DPT + 拟时序核算命运）、细胞分组列
- **本程序实际输出**：数据质量指标与质量图；自动分群 + UMAP 图；群间连接（PAGA）；有剪接层时：速度矩阵、箭头图、速度伪时序；有速度时：终末状态与命运概率；给了起点时另有 DPT 拟时序；一份汇总的 A 生物学报告 + B 技术复现报告
- **CPU / GPU**：纯 CPU；小数据约 20–40 秒，大数据会明显变慢
- **数据限制**：需要 X 为原始计数；velocity 需要 spliced/unspliced 两层
- **一句话警示**：一次跑完：质控 → 自动分群 → PAGA →（有剪接层）速度 →（有速度或起点）命运概率。每一步的结果与限制都会分开写清，不会把推断当成事实。
- **官方来源**：https://scanpy.scverse.org/en/stable/

**适合回答的问题**：我不想一个个挑方法：能不能丢进一个矩阵，自动跑完体检、分群、轨迹，有剪接层就加速度和命运，最后给我一份报告？

**不能回答什么**：它不会替你判断生物学结论对不对，也不会把推断写成事实。

**必需输入**

- X 矩阵：每行一个细胞、每列一个基因（h5ad 文件）
- 细胞 ID 与基因 ID：必须唯一，且与矩阵行列一一对应

**可选信息**

- spliced / unspliced 原始计数层（有这两层才会自动加速度与命运）
- 起始细胞 ID + 生物学依据（有就用 DPT 拟时序；没有也能用速度图算命运）
- 物种、组织、供体列、分组列

**计算过程（简版）**

1. **数据体检**：先判断 X 是计数、已取对数还是已缩放，决定要不要归一化。
2. **预处理与分群**：归一化/取对数 → 高变基因 → PCA → 邻域 → UMAP → 自动 Leiden 分群。
3. **群间连接**：用 PAGA 汇总群与群之间的连接强度（无向）。
4. **速度（有剪接层时）**：scVelo stochastic 估计基因空间速度，投影到 UMAP 并算速度伪时序。
5. **命运（有速度或起点时）**：CellRank 用速度图或 DPT 拟时序识别终末状态，估计每个细胞的命运概率。
6. **出报告**：把每一步的结果、指标与限制写成 A 生物学报告与 B 技术复现报告。

**方法通常能输出**

- 质控与降维图
- 细胞分群
- 群间连接
- 速度与伪时序
- 终末状态与命运概率

**本程序目前实际输出**

- 数据质量指标与质量图
- 自动分群 + UMAP 图
- 群间连接（PAGA）
- 有剪接层时：速度矩阵、箭头图、速度伪时序
- 有速度时：终末状态与命运概率；给了起点时另有 DPT 拟时序
- 一份汇总的 A 生物学报告 + B 技术复现报告

**本程序明确不输出**

- 细胞类型注释
- 双细胞/环境 RNA 校正
- 有向谱系的实验验证
- 轨迹准确率评测

**主要假设**

- X 的数值状态可由数值外观判断（计数 / 已取对数 / 已缩放）
- 有剪接层时，剪接计数能代表真实的剪接动态
- 默认分群分辨率 1.0 适合当前数据量级

**解释边界**

- 一键不等于自动得出结论：每一步的限制都会写进报告。
- 没有剪接层时不会硬凑速度；没有起点时不会硬凑方向。
- 终末状态、命运概率与候选基因都是模型推断，需要独立证据。

**运行环境与状态**

- 环境：基础环境 .venv（scanpy 1.11 / scvelo 0.3.4；可选 cellrank 2.0.7）
- 设备：纯 CPU；240 细胞模拟数据约 20–25 秒
- 数据限制：本机：矩阵合计约 3 GB 内存；CellRank 命运概率限 ≤6000 细胞
- 本机验证情况：已在本机 CPU 上跑通模拟数据（含速度与命运）；真实数据待验证。

## 轨迹与分群：细胞群之间怎么连接？从一个有依据的起点看，细胞按什么相对顺序排列？

### 扩散拟时序 DPT（`dpt`，Scanpy Diffusion Pseudotime）

- **当前状态**：可运行
- **必需输入**：起始细胞 + 生物学依据
- **可选输入**：细胞分组（用于给群排序）
- **本程序实际输出**：每个细胞的 DPT 拟时序（含可达性诊断）；按拟时序着色的图；沿拟时序的探索性基因趋势
- **CPU / GPU**：CPU 可运行
- **数据限制**：不连通区域可能没有可解释的拟时序
- **一句话警示**：必须指定起点并说明依据；拟时序是相对顺序，不是真实小时数，也不是 RNA velocity。
- **官方来源**：https://scanpy.scverse.org/en/stable/generated/scanpy.tl.dpt.html

**适合回答的问题**：从一个有依据的起点细胞出发，其他细胞按什么相对顺序远离它？

**不能回答什么**：它不能给出真实时间（例如第几天），也不能说明细胞最终分化成了什么。

**必需输入**

- X 矩阵：未归一化的原始计数（cells × genes）
- 起始细胞 ID：数据中真实存在的细胞名
- 起点依据：一句话说明为什么它是起点（实验或文献理由）

**可选信息**

- 细胞分组列（便于按群排序阅读；不提供也能算）

**计算过程（简版）**

1. **归一化与选基因**：每个细胞缩放到相同总量、取对数，保留变化最大的基因。
2. **建邻居与扩散图**：按表达相似度连成邻居图，再计算扩散分量（diffusion map）。
3. **从起点算距离**：以你指定的起点为 0，算每个细胞的相对距离，这就是 DPT 拟时序。
4. **可达性诊断**：统计多少细胞拿到有限数值；不连通的区域可能没有可解释的值。
5. **沿拟时序看趋势**：按拟时序着色出图，并给出沿这个顺序变化的探索性基因趋势。

**方法通常能输出**

- 每细胞拟时序数值
- 按拟时序着色的图
- 沿顺序变化的基因趋势

**本程序目前实际输出**

- 每个细胞的 DPT 拟时序（含可达性诊断）
- 按拟时序着色的图
- 沿拟时序的探索性基因趋势

**本程序明确不输出**

- 真实天数或小时数
- RNA 速率与方向
- 细胞命运概率
- 自动替你挑起点
- 细胞类型注释

**主要假设**

- 起点选对了，顺序才有意义
- 表达相似度可以近似表示细胞状态接近
- 同一连通区域内的距离可比

**解释边界**

- 拟时序是相对顺序的数值，不是真实时间，不能换算成小时。
- 换一个起点，几乎所有细胞的顺序都会变，所以起点与依据必须一起报告。
- 不连通的群可能拿不到数值，不能把缺失当成 0 或“排在最后”。
- 它不使用剪接信息，不能当作 RNA 速率结果。

**运行环境与状态**

- 环境：基础环境 .venv：scanpy 1.11.5 / anndata 0.12.19
- 设备：纯 CPU；模拟数据端到端约 20 秒
- 数据限制：不连通区域可能没有可解释的拟时序；本机：矩阵合计约 3 GB 内存
- 本机验证情况：已在本机 CPU 上用模拟起点跑通（240 个细胞全部可达）；真实数据未验证。

### 自动分群（Leiden + UMAP）（`leiden`，Scanpy Leiden (igraph)）

- **当前状态**：可运行
- **必需输入**：无
- **可选输入**：无
- **本程序实际输出**：每个细胞的群编号；UMAP 二维图（按群着色）；群大小表；每群相对高表达基因（描述性）
- **CPU / GPU**：纯 CPU；UMAP 在万级细胞上约数十秒
- **数据限制**：细胞越多 UMAP 越慢；本机矩阵合计约 3 GB 内存
- **一句话警示**：分群结果取决于分辨率和邻域参数，不等于“真实细胞类型”；群内高表达基因只是描述性线索。
- **官方来源**：https://scanpy.scverse.org/en/stable/generated/scanpy.tl.leiden.html

**适合回答的问题**：在没有现成标签的情况下，这批细胞可以分成几群？每群大致有什么特征？

**不能回答什么**：它不能说明这些群就是“真实细胞类型”，也不能给出群与群之间的先后关系。

**必需输入**

- X 矩阵：未归一化的原始计数（cells × genes）
- 细胞与基因 ID：唯一，且与矩阵行列一一对应
- 在界面上确认“X 是原始计数”后才会按原始计数处理

**可选信息**

- 分群分辨率（默认 1.0；调大得到更多、更细的群）
- 是否画 UMAP 图（默认画；关掉只出群编号和表）

**计算过程（简版）**

1. **归一化与选基因**：每个细胞缩放到相同总量、取对数，再选变化最大的基因。
2. **降维与找邻居**：用 PCA 压缩表达谱，再按表达相似度为每个细胞找邻居。
3. **按邻居分组**：Leiden 把互相连接紧密的细胞划成同一群，得到群编号。
4. **画到二维图上**：用 UMAP 把细胞摊到平面，按群着色，便于看分群是否合理。
5. **汇总每群**：统计群大小，并列出每群相对高表达的基因作为线索。

- **官方来源**：https://cellrank.readthedocs.io/en/stable/

**适合回答的问题**：在已有起点和拟时序的前提下，细胞走向各终末状态的相对可能性有多大？

**不能回答什么**：它不能证明真实的细胞谱系，也不能替代实验上的命运追踪。

**必需输入**

- X 矩阵：未归一化的原始计数（cells × genes）
- 起始细胞 ID：数据中真实存在，并有一句话说明为什么是起点
- 前置条件：程序先用该起点做 DPT；拟时序不可用时不硬算命运概率

**可选信息**

- 细胞分组列（辅助识别终末状态；不给时程序先自动分群）
- 终末状态个数（默认 3，可设 2–10）

**计算过程（简版）**

1. **先算拟时序**：内部先做 DPT，得到每个细胞相对起点的位置。
2. **建转移矩阵**：把拟时序换算成细胞之间“更可能往哪走”的转移概率。
3. **识别终末状态**：把细胞聚成若干宏观状态，再挑出没有明显出路的终末状态。
4. **算命运概率**：从每个细胞出发做随机游走，统计先到各终末状态的比例。
5. **找相关基因**：列出与命运概率相关的候选基因，并按概率给细胞着色。

**方法通常能输出**

- 终末状态
- 命运概率
- 基于命运的概率图
- 相关基因趋势

**本程序目前实际输出**

- 终末状态识别结果
- 每个细胞到各终末状态的命运概率
- 按命运概率着色的图
- 驱动命运概率的候选基因（描述性）

**本程序明确不输出**

- 已验证的真实谱系
- 真实时间
- 上游速度模型
- 细胞类型注释
- 跨模型横向打分的排名

**主要假设**

- 起点与拟时序可信
- 终末状态由算法从同一份数据里挑出
- 随机游走能近似细胞的去向

**解释边界**

- 命运概率是模型推断，不是实验观测到的谱系。
- 终末状态的个数会明显改变结果，且需要生物学确认，不能只看图下结论。
- 只识别出一个终末状态时，所有细胞的概率都是 1，数值没有区分度，相关基因那一步也会算不出来（模拟数据上已出现）；报告会写明这一点。
- 它属于下游命运分析，不能与上游速度模型放在同一张排行榜里比较。

**运行环境与状态**

- 环境：基础环境 .venv：cellrank 2.0.7 / scanpy 1.11.5 / scvelo 0.3.4
- 设备：纯 CPU；比 DPT 慢一些
- 数据限制：需要可用的 DPT 拟时序（本程序内部先生成）；本机未装 petsc4py，要把细胞×细胞矩阵稠密化，细胞超过约 6000 个会被拒绝并要求先用子集
- 本机验证情况：已在本机 CPU 上用 cellrank 2.0.7 独立跑通 PseudotimeKernel + GPCCA 与命运概率（模拟数据；只识别到 1 个终末状态，驱动基因那一步失败）；适配器真实数据未验证。
