# 本机硬件与运行策略

系统配置（2026-10-24 读取）：**Intel i5-1240P（12 核 / 16 逻辑处理器）**、**16 GB 内存**、
**Intel Iris Xe 集成显卡**，**未发现 NVIDIA 独立 GPU**，因此不能使用 CUDA。
这是配置快照，不是完整硬件故障检测；也不应把依赖下载超时直接归因于硬件。

## 默认策略

- **纯 CPU**：中文界面、AnnData/Scanpy、Plotly、scVelo、Leiden/UMAP、DPT/PAGA、CellRank 全部可在 CPU 上跑。
  **CUDA 不是这些能力的必要条件**；本工具不安装 CUDA、不安装 NVIDIA 驱动。
- **单任务、单线程**：计算子进程固定 `OMP_NUM_THREADS=1` 等线程上限，避免 16 GB 机器被并行任务占满；
  代价是慢一些，但更稳、更容易复现。任务串行执行（同一时间只有一个在跑）。
- **可选神经栈默认不装**：RegVelo 的 CPU 神经环境（PyTorch + scvi-tools）需要数 GB 磁盘与较长下载，
  本机不自动安装；需要时用 `python install.py --include-regvelo` 单独装。
- **CellRank 已装**（2.0.7，纯 Python 依赖，约十几 MB），可直接做下游命运概率。

## 这台电脑上的实际耗时（240 细胞 × 120 基因模拟数据，含解释器启动）

| 方法 | 耗时 |
|---|---|
| 质控 / 模拟示例 | 约 2 秒 |
| 自动分群 / DPT / PAGA | 约 17–18 秒 |
| scVelo stochastic | 约 17 秒 |
| scVelo dynamical | 约 21 秒 |
| CellRank 命运概率 | 约 21 秒 |

耗时主要由**解释器启动 + 库导入**构成；真实数据的耗时随细胞数、基因数、邻域规模增长。
不要用这些数字给方法排名（不同方法做的事不同）。

## 数据规模建议（16 GB 内存）

| 细胞数 | 建议 |
|---|---|
| < 2 千 | 所有已接入方法都适合直接跑 |
| 2 千 – 2 万 | 质控/分群/轨迹没问题；velocity 建议先看剪接覆盖率，dynamical 可能较慢 |
| 2 万 – 5 万 | 建议先用随机子集调通参数；UMAP 与 velocity 会明显变慢 |
| > 5 万 | 本原型不适合直接全量，考虑子集或改用 backed/Zarr 方案（尚未实现） |

**CellRank 额外限制**：不装 `petsc4py` 时 GPCCA 的 Schur 分解要把细胞×细胞矩阵稠密化，
所以程序在 **> 6000 细胞**时直接拒绝并给出原因（建议先做受控子集，或改用 DPT + PAGA 看方向）。

## 空间

C 盘当时可用约 24.7 GiB，D/F/G 盘各 55–128 GiB。主环境约 0.8 GB；可选 RegVelo 环境会再占数 GB。
结果目录随任务增长（每个任务含输入副本、图、报告与 AnnData），定期清理 `results/` 下的旧任务即可。

## 科学策略

- 先 QC 和分群，再谈方向；**只有确认过剪接层来源**才做 velocity。
- 真实数据先用科学上可解释的受控子集验证参数（并记录筛选方法），避免随机删掉稀有群。
- 潜在时间不是真实时间；箭头不是谱系证据；命运概率不是事实；候选基因不是因果。
- 不存在脱离数据规模和问题的“最佳模型”。本程序不输出排行榜。

不需要为了启动这个工具购买显卡；需要更快神经网络方法时，再评估是否值得投入 GPU 或云资源。
