# 模型支持矩阵

由 `tools/build_support_matrix.py` 从 `cellflow/registry.py` 生成，
状态按本机安装情况实时判定。

| 方法 | 类别 | 官方实现 | 必需输入 | 运行环境 | 本机状态 | 主要限制 |
|---|---|---|---|---|---|---|
| 一键分析（推荐流程） | 一键分析（推荐） | `CellFlow auto pipeline` | 无 | `.venv` | 可运行 | 一键不等于自动得出结论：每一步的限制都会写进报告。；没有剪接层时不会硬凑速度；没有起点时不会硬凑方向。；终末状态、命运概率与候选基因都是模型推断，需要独立证据。 |
| 数据质控与 PCA | 质控与结构 | `Scanpy QC / PCA` | 无 | `.venv` | 可运行 | PCA 上离得远只是表达谱不同，不等于细胞类型或分化方向不同。；线粒体比例高不必然等于坏细胞，需结合组织与实验判断。；本程序不套用通用阈值删细胞，是否过滤由你决定。 |
| 模拟教学示例 | 演示与教学 | `Built-in synthetic demo` | synthetic | `.venv` | 可运行 | 模拟时间来自数据生成脚本，不是模型推断，也不是真实时间。；模拟数据只有 240 个细胞，跑得通不代表你的真实数据也跑得通。；不要把示例报告里的图形和数值当成方法效果的比较依据。 |
| 自动分群（Leiden + UMAP） | 轨迹与分群 | `Scanpy Leiden (igraph)` | 无 | `.venv` | 可运行 | 群编号只是算法给的分组，不是细胞类型命名；要命名得另找标记基因或参考数据。；改一下分辨率，群的数量和边界几乎一定会变，报告里的群数要和参数一起看。；群内高表达基因是按“群内均值减群外均值”排的，没有做显著性检验，不是标记基因。；UMAP 上 |
| 扩散拟时序 DPT | 轨迹与分群 | `Scanpy Diffusion Pseudotime` | root | `.venv` | 可运行 | 拟时序是相对顺序的数值，不是真实时间，不能换算成小时。；换一个起点，几乎所有细胞的顺序都会变，所以起点与依据必须一起报告。；不连通的群可能拿不到数值，不能把缺失当成 0 或“排在最后”。；它不使用剪接信息，不能当作 RNA 速率结果。 |
| PAGA 群间连接 | 轨迹与分群 | `Scanpy PAGA` | groups | `.venv` | 可运行 | 连接强是**无向**的，不能读成“A 分化成 B”；方向要另找证据（速度、拟时序、实验时间）。；群被标错、分得太粗或太细，都会直接改变结果。；“若同时提供起点”给出的群平均拟时序只是方向线索，仍需与其他证据一起看。 |
| scVelo · deterministic（稳态） | 速度推断 | `scVelo steady-state` | raw_SU | `.venv` | 可运行 | 稳态假设在快速分化或瞬态系统中往往不成立，此时方向可能整体偏。；它是 scVelo 官方的 deterministic 模式，不是本程序自写算法。；箭头与内部一致性不能证明真实分化方向。 |
| scVelo · stochastic | 速度推断 | `scVelo stochastic` | raw_SU | `.venv` | 可运行 | 箭头方向是模型推断；二维投影会让方向看起来“更确定”，实际可能失真。；速度一致性高只说明内部自洽，不说明方向正确。；高速度基因是候选，不是已验证的因果驱动基因。；与 dynamical 的结果不能按似然/损失直接排名。 |
| scVelo · dynamical | 速度推断 | `scVelo dynamical` | raw_SU | `.venv` | 可运行 | 潜在时间没有用实验时间标定，只能当相对顺序看。；似然高只说明在这个模型里拟合得更好；高似然基因不是已验证的因果驱动基因。；拟合失败率高说明数据没覆盖到相应动力学状态，不是“参数没调好”。；它的数值不能与 stochastic 或其他模型的损 |
| CellRank 2 · 命运概率 | 下游命运分析 | `CellRank 2 (PseudotimeKernel)` | root | `.venv` | 可运行 | 命运概率是模型推断，不是实验观测到的谱系。；终末状态的个数会明显改变结果，且需要生物学确认，不能只看图下结论。；只识别出一个终末状态时，所有细胞的概率都是 1，数值没有区分度，相关基因那一步也会算不出来（模拟数据上已出现）；报告会写明这一点 |
| RegVelo · 带先验的调控动力学 | 调控动力学 | `RegVelo 0.4.2` | raw_SU、prior_GRN | `.venv-regvelo` | 实验接入 | 这是实验接入：本机未安装独立环境、未实际训练，界面会把它拦在“不可运行”。；即使以后训练成功，模型推断的调控边也只是假设，不是验证过的因果关系。；先验错一行（方向反了、ID 不匹配、物种不对），结果会跟着错而不报警。 |
| veloVI · 变分速度与不确定性 | 速度推断 | `scvi-tools VELOVI` | raw_SU | `.venv-velovi` | 可运行 | 训练损失不能与别的模型的似然/损失直接排名。；不确定性小不等于结论对，它只反映模型内部的自信程度。；默认训练轮数有限，真实数据建议加到收敛并看损失曲线。；它和 scVelo 的方向差异应看作“模型不确定性”，而不是谁对谁错。 |
| DeepVelo · 细胞相关动力学 | 速度推断 | `DeepVelo (bowang-lab)` | raw_SU | `.venv-deepvelo` | 尚未接入 | 尚未接入：这里指 bowang-lab 的 DeepVelo，同名其他项目不是同一实现。；官方实现要求较旧的 Python 与 DGL，与当前基础环境冲突，必须单独建环境。；本机没有 NVIDIA 显卡，官方默认 GPU 的设置在 CPU  |
| UniTVelo · 共同时间动力学 | 速度推断 | `UniTVelo` | raw_SU | `.venv-unitvelo` | 尚未接入 | 尚未接入：只有注册与说明，没有可调用代码。；“共同时间”是较强的假设，要结合研究系统判断，不能因为图更平滑就选它。；TensorFlow 栈与当前基础环境不兼容，需要单独安装并在本机验证；16 GB 内存下训练会更慢，建议先用受控子集。 |
| VeloAE · 低维速度 | 速度推断 | `VeloAE (veloproj)` | raw_SU | `.venv-veloae` | 尚未接入 | 尚未接入：只有注册与说明，没有可调用代码。；低维速度与基因空间速度不能逐元素比较，需要额外映射才能对上基因。；需要 PyTorch Geometric，安装较重；本机只有 CPU，训练慢。 |
| dynamo · 动力学与向量场 | 调控动力学 | `dynamo-release` | protocol | `.venv-dynamo` | 尚未接入 | 尚未接入：只有注册与说明，没有可调用代码。；普通 scRNA 数据不能替代代谢标记数据，时间也不能由程序补出来。；完整安装体积较大；本机 16 GB 内存与核显更适合先跑受控子集。 |
| MultiVelo · 多组学动力学 | 调控动力学 | `MultiVelo` | raw_SU、matched_ATAC | `.venv-multivelo` | 尚未接入 | 尚未接入：只有注册与说明，没有可调用代码。；只有 scRNA 时条件不成立，程序会直接说明缺 ATAC，而不是硬着头皮跑。；即使跑通，“染色质先变化”也只是模型内的相对时序，不是因果证明。 |

## 说明

- “本机状态”按当前解释器是否安装了所需依赖判断；隔离环境（`.venv-velovi`）单独判断。
- 未标为可运行的方法不会被执行；界面会显示缺什么。
- 不同方法的似然/损失/时间尺度不可直接比较。
